# 代码规约

## 1. 技术选型
本项目采用前后端分离的 MVC 架构，统一使用以下技术栈：
- 后端：Spring Boot 2.0.x、Java 8
- 持久层：MyBatis（XML Mapper）
- 数据库：MySQL 8.x，存储引擎统一使用 InnoDB
- 前端：Vue 2.x
- 接口风格：RESTful API，数据交换格式统一为 JSON
- 项目管理：后端使用 Maven，前端使用 npm


## 2. 总体架构

系统采用前后端分离模式。后端遵循 MVC 分层，调用方向如下：

`Controller -> Service -> Mapper -> MySQL`

各层只允许向下依赖，禁止跨层调用：

- Controller：接收请求、校验参数、调用 Service、封装响应，不编写业务逻辑。
- Service：处理业务规则和事务，通过 Mapper 访问数据。
- Mapper：只负责数据库读写，不处理业务逻辑。
- Model：按职责划分为 Entity、DTO、Query 和 VO，禁止用数据库实体直接承载所有接口参数和响应。
- Vue：按页面、组件、接口和状态管理分层，不在视图中直接拼接请求或处理复杂业务。

## 3. 后端工程规范

### 3.1 推荐目录

```text
src/main/java/com/company/project
├── config          # 配置类
├── controller      # 控制器
├── service         # 业务接口
│   └── impl        # 业务实现
├── mapper          # MyBatis Mapper 接口
├── model
│   ├── entity      # 数据库实体
│   ├── dto         # 请求对象
│   ├── query       # 查询条件
│   └── vo          # 响应对象
├── common          # 通用响应、常量等
├── exception       # 异常及全局异常处理
└── util            # 无业务状态的工具类

src/main/resources
├── mapper          # MyBatis XML
├── application.yml
└── application-{env}.yml
```

### 3.2 命名规范

- 包名：全小写，如 `com.company.project.controller`。
- 类名：大驼峰；控制器以 `Controller` 结尾，业务接口以 `Service` 结尾，实现类以 `ServiceImpl` 结尾，数据访问接口以 `Mapper` 结尾。
- 方法、变量：小驼峰，名称应表达业务含义，禁止使用无意义缩写。
- 常量：全大写，下划线分隔。
- DTO、Query、VO 按业务命名，如 `UserCreateDTO`、`UserPageQuery`、`UserDetailVO`。
- 布尔字段避免使用含义不清的名称，优先使用 `enabled`、`deleted` 等。

### 3.3 Controller 规范

- 使用 `@RestController`，模块统一配置 `@RequestMapping`。
- 根据语义使用 `GET`、`POST`、`PUT`、`DELETE`。
- 路径使用小写名词，多个单词使用短横线，不在路径中使用动词。
- 请求体使用 `@RequestBody`，路径参数使用 `@PathVariable`，查询参数封装为 Query 对象。
- 参数校验使用 Bean Validation（`@Valid` 或 `@Validated`）。
- Controller 不直接调用 Mapper，不开启事务，不捕获后又忽略异常。
- 所有接口返回统一响应结构。

统一响应建议：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

分页响应中的 `data` 至少包含 `list`、`pageNum`、`pageSize` 和 `total`。

### 3.4 Service 与事务规范

- Service 接口定义业务能力，具体实现放在 `impl` 包。
- 一个公开方法应完成一个明确的业务用例。
- 涉及多次写操作时，在 Service 实现的 `public` 方法上使用 `@Transactional(rollbackFor = Exception.class)`。
- 只读查询原则上不加事务；确需事务时使用 `readOnly = true`。
- 禁止在同一个类中通过 `this` 调用带事务的方法并期待事务生效。
- 业务异常统一抛出自定义异常，由全局异常处理器转换为规范响应。
- 不得在事务中执行耗时的远程调用；无法避免时应明确超时和失败处理策略。

### 3.5 MyBatis 规范

- Mapper 接口与 XML 文件一一对应，namespace 必须是 Mapper 接口的全限定名。
- XML 文件放在 `resources/mapper` 下，文件名与 Mapper 接口一致。
- 多参数方法必须使用 `@Param` 明确命名。
- 查询字段必须显式列出，禁止使用 `SELECT *`。
- SQL 关键字大写，复杂 SQL 合理换行并保持缩进一致。
- 表字段与 Java 属性不一致时，使用 `resultMap` 显式映射；不得依赖难以察觉的隐式转换。
- 动态 SQL 必须使用 `#{}` 绑定参数，禁止用 `${}` 拼接用户输入。
- 批量操作使用 `foreach`，并限制单批数据量。
- 更新和删除必须带明确条件；代码评审时重点检查全表更新、全表删除风险。
- Mapper 只返回实体、VO、基础类型或集合，不返回含义不明的 `Map`。

## 4. MySQL 8 规范

- 默认字符集使用 `utf8mb4`，排序规则在项目内保持一致。
- 表名、字段名使用小写下划线命名，禁止使用 MySQL 保留字。
- 每张业务表应包含主键；主键统一使用 `BIGINT`，生成策略在项目内保持一致。
- 金额使用 `DECIMAL`，禁止使用 `FLOAT` 或 `DOUBLE`。
- 时间使用 `DATETIME` 或 `TIMESTAMP`，Java 侧统一时区并避免字符串形式存储时间。
- 状态和类型字段使用有明确注释的数值或短字符串编码。
- 需要逻辑删除时统一使用 `deleted` 字段，并确保所有查询遵循相同规则。
- 表和字段必须添加注释；重要变更必须提供可审查、可回滚的 SQL 脚本。
- 索引应根据实际查询条件设计。联合索引遵循最左匹配原则，避免重复和无效索引。
- 禁止在索引列上进行导致索引失效的函数计算或隐式类型转换。
- 分页查询必须有稳定排序；大数据量场景避免深分页。
- 禁止依赖 MySQL 5.x 的宽松行为；SQL 应兼容 MySQL 8 默认 SQL 模式。

## 5. 前端 Vue 2 规范

### 5.1 推荐目录

```text
src
├── api             # 接口定义
├── assets          # 静态资源
├── components      # 通用组件
├── router          # 路由
├── store           # Vuex
├── utils           # Axios 封装、工具函数
├── views           # 页面级组件
├── App.vue
└── main.js
```

### 5.2 编码规范

- 使用 Vue 2 Options API，不使用 Vue 3 Composition API、`setup`、`ref` 等语法。
- 组件文件使用大驼峰命名，如 `UserTable.vue`；路由 path 使用小写短横线。
- `data` 必须为返回对象的函数；props 必须声明类型，重要属性应声明默认值或 required。
- 计算属性使用 `computed`，避免在模板中编写复杂表达式。
- 列表渲染必须使用稳定且唯一的 `key`，禁止把数组下标作为可变列表的 key。
- 禁止直接修改 props；父子组件通过 props 和事件通信。
- 可复用状态放入 Vuex，页面局部状态保留在组件内，禁止将所有状态都放入 Vuex。
- 页面组件负责组织业务，通用组件保持单一职责，不直接依赖特定页面接口。
- 用户输入必须校验，提交期间应防止重复请求，并提供加载、成功和失败反馈。

### 5.3 请求规范

- Axios 必须统一封装实例、baseURL、超时、请求拦截器和响应拦截器。
- 接口按业务模块放在 `src/api`，组件内不得直接写请求 URL。
- Token 等认证信息由请求拦截器统一添加。
- 统一处理未登录、无权限、网络错误和业务错误；不得静默吞掉异常。
- 前端展示后端返回的信息前应考虑安全性，禁止直接使用未经信任的 HTML。

## 6. 接口约定

- 请求和响应字段统一使用小驼峰命名，数据库字段使用小写下划线命名。
- 日期时间统一使用明确格式（推荐 `yyyy-MM-dd HH:mm:ss`）并约定时区。
- ID 超出 JavaScript 安全整数范围时，后端以字符串返回，前端不得转为 Number。
- HTTP 状态码表达传输层结果，响应 `code` 表达业务结果，两者语义不得冲突。
- 新增、修改接口不得随意变更已有字段含义；不兼容变更必须进行版本管理。
- 敏感字段（密码、密钥、完整证件号等）不得出现在日志或普通接口响应中。

## 7. 配置、日志与安全

- 环境配置使用 `application-{env}.yml`，禁止把密码、密钥、Token 提交到代码仓库。
- 配置项必须有明确前缀和含义，禁止在业务代码中散落魔法值。
- 使用统一日志框架和参数化日志，如 `log.info("userId={}", userId)`，禁止使用 `System.out.println`。
- 异常日志应包含必要上下文和堆栈，但不得记录密码、Token 等敏感信息。
- 所有外部输入均视为不可信，必须进行长度、格式、范围和权限校验。
- 数据库访问使用参数绑定防止 SQL 注入；页面输出应防止 XSS。
- 权限校验必须由后端执行，前端路由或按钮控制不能替代后端鉴权。

## 8. 测试与交付

- Service 的核心业务规则必须编写单元测试。
- Mapper 的复杂 SQL 应进行集成测试，覆盖正常、空结果、边界和异常数据。
- Controller 测试应覆盖参数校验、权限、成功响应和异常响应。
- 前端至少验证核心页面的加载、查询、提交、错误提示和重复提交处理。
- 提交前必须通过编译、测试和静态检查，不得提交临时代码、调试输出或无关格式化改动。
- 数据库结构变更、配置变更和接口变更必须随代码一并说明。

## 9. 禁止事项

- 禁止 Controller 直接访问数据库。
- 禁止在 Mapper 或 XML 中编写业务流程。
- 禁止使用字符串拼接生成含用户输入的 SQL。
- 禁止返回数据库实体作为所有接口的通用响应对象。
- 禁止前端组件散落重复请求逻辑或硬编码服务地址。
- 禁止引入 Vue 3、Spring Boot 3 或与既定版本不兼容的依赖和写法。
- 禁止提交密钥、生产账号、真实敏感数据和生成目录。
